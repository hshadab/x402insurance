How It Works

The insurance service runs on AWS Bedrock AgentCore (port 8080). This dashboard is a read-only monitoring UI hosted on App Runner.

1

Agent Buys Coverage

An AI agent sends a POST /insure request to the AgentCore service with an x402 V2 payment header. Premium is 1% of coverage amount. Payment is verified and settled on-chain via the x402.org facilitator.

2

API Call Fails

The insured merchant API returns an error (HTTP 500-504) or an empty response. The agent captures the full HTTP response as evidence for the claim.

3

Submit Claim & Generate Proof

Agent sends POST /claim to the AgentCore service. The server re-fetches the merchant URL for fraud detection, then runs the Jolt Atlas prover binary. This executes a trained ONNX neural network (claim_classifier.onnx — a 2-layer MLP classifying failure vs. success) inside a zkML circuit, producing a cryptographic proof of correct model execution.

4

Verify & Refund On-Chain

The zkML proof is verified — confirming the ONNX model was executed correctly over the claimed inputs (http_status, body_length, coverage_amount) and that the output classifies the response as a failure. If valid, USDC is transferred on Base Mainnet to the agent's wallet. The proof is publicly auditable via POST /verify on the AgentCore service.

x402 Payment Flow

        
Endpoints marked x402 require payment. Follow this flow:

        

            
1
POST without payment
Server responds 402 with accepts array describing amount, asset, payTo.

            
2
Sign EIP-712 typed data
Build payment message with amount, asset, nonce, timestamp. Sign with wallet key.

            
3
Retry with PAYMENT-SIGNATURE header
Base64-encode the signed payload. Server verifies via x402.org facilitator and settles on-chain.

Claims


    
POST/claimSubmit claim
x402
▸

        
Submit a claim for a failed API call. Server re-fetches merchant URL, generates Jolt Atlas zkML proof over ONNX model inference, and issues USDC refund if valid.

        
Fraud Detection: The server independently re-fetches the merchant URL to verify the failure. If the agent claims 5xx but the server sees 200, the claim is flagged.

        
Request Body

        
FieldTypeDescription

        
policy_idstringREQUIREDActive policy ID

        
http_response.statusintegerREQUIREDHTTP status code (e.g. 503)

        
http_response.bodystringREQUIREDResponse body

        
http_response.headersobjectoptionalResponse headers

        

        
Query: ?async=true for async processing
